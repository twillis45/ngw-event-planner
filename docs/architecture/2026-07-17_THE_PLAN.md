## 0 · ⛔→✅ Legacy is not being deleted — RULED, CLOSED

**`src/App.js` is not "the legacy host shell." It is that AND the entire planner app**, in one 46,988-line file.
`index.js` mounts `<App/>` at `/`; App.js imports `CommandCenter` (planner L3, `:137`, 17 refs) and holds
`EventCommTab` (L4) and `DailyBriefing` (L2). **There is no `plannerv2`.**

**Two independent reasons deleting the CRA is destructive:**
1. It deletes the **planner product** — no replacement, no port.
2. It breaks **hostv2 too.** `hostv2/vite.config.js` aliases `@app` → `../src`, and the go-forward host shell
   imports **103 modules** from that tree — including `CommandCenter` itself and ~90 `lib/` engines. hostv2 is a
   Vite front end riding on the CRA's source, not a standalone app.

> **✅ HOST RULING, 2026-07-17: "legacy is not going to be deleted any time soon."** The deletion row — the single
> most dangerous item in every prior plan, and the one most confidently marked "mechanical" — is **CLOSED, not
> scheduled.** It returns only if a `plannerv2` program is chartered. The `~25 MB CRA still ships` /
> `react-scripts` build weight is real but is a **bundle-size** concern, not a deletion trigger.

The file's own freeze header — *"FROZEN — legacy CRA host shell"* — names half of what the file is, and misled
every "delete legacy" reasoning step across every plan. Legacy stays **frozen and donor-only** (security/data-loss
fixes + shared `lib/` engine work only); it is not deleted.

## 6 · The method — prove the plan

**The host's diagnosis:** *"we keep getting to steps in plan that are reversed after investigated."* That's not bad
luck; it's how plans are built. Premises proven false so far: *cost matters* (a nickel/event) · *one guard fits
every AI job* (extraction ≠ answering) · *the donor's value is spent* (it's the planner) · *we deploy to an edge*
(Render free, single region) · *the prefix is cacheable* (under the floor) · *an entitlement boundary exists* (auth
≠ payment) · *the $39 pass gates something* (nothing) · *grounding is enforced* (it warns) · *one model everywhere*
(App.js BYOK haiku).

**Before sequencing work on a row, extract its premise and test it — at planning time, not at the moment of action,
which is the most expensive place to find out.** A row that can't name a testable premise isn't a plan row; it's an
intention. The method only earns trust by catching its author: two of the reversals above were this doc's own
predecessor, re-proven an hour after it was written.
