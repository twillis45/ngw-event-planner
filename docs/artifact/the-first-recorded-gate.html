What was believed, and what replaced it

A green Pages run plus a matching CSS hash means the deploy is current.

The deployed JS chunk did not match the local build, and that looked like the repo's recorded staleness trap firing. It was not. CI injects build variables the local build lacks, so content and therefore hash differ legitimately — while the CSS hash matched exactly, which made the mismatch look worse than it was. Comparing a deployed hash against a local build proves nothing. Probe the deployed bundle for a feature shipped in a known commit instead.

Sending is blocked on building transport.

It was blocked on the transport already built never having had an address to send to: one of 24 draft call sites passed a vendor id, and zero of 126 seeded vendors carried an email. The send button rendered on no event in the app.

Seven tests can never fail.

Four. The census counted three _*Capture specs among them — but each declares "not a gate" in its own first line, carries the _ prefix convention, and writes to a gitignored directory. They are capture tools for board sittings that are meant to lie dormant until asked for. Published as seven here before it was checked; the smallest true number is four, and it is the one that matters because those four are real tests believed to be running.

No standing delegation exists for this project.

Written into a gate record earlier the same day, and false. The owner's standing instruction was to convene the review board for decisions — which is exactly the delegation the spine describes. It was read as per-project and scoped to the projects whose records happened to name it, then cited as a reason to stop. A hook caught it by reading ruledBy out of the gate file. The earlier record stands beneath the ruling rather than being edited away.

Three faults red-proofed, so the durability check holds.

One escaped. Removing the call from the write path left all twelve tests green, because "a refused write does not ask" is vacuously true when nothing ever asks. The positive assertion was missing: that a successful write asks at all. Added, and the fault now fails. Recorded as an escape rather than quietly fixed — an escape measures the suite, not the fault.

A gate that fails locally is failing.

gate:cra exits 1 here and passes in CI on the same commit. The warning it reports is demonstrably false — it calls COST_PROVENANCE_TYPE unused while it is used at governedFieldTypes.js:342, inside an object literal that closes at 343. A subagent that ran the command concluded main was red; the command was reported honestly and the inference was not checked. Cause undetermined, CI is authoritative, and the divergence is recorded rather than papered over.

Three checkboxes on stage 7 were open work.

They were fixed — the admin console's key mismatch, three of four orphaned recovery functions, the day-of dead-end probe — and stayed unchecked for up to two days after landing, found only when asked "how was this missed." The pattern each time: a fix landed, a NEW static ✓ line was added confirming it, and the OLD unchecked line describing the original problem was never revisited in the same edit. The card grew a line saying "fixed" sitting directly above a checkbox still saying "broken." Caught by reading the actual source for every open item rather than trusting either line. The rule now: when a fix lands, close the checkbox it answers in the SAME edit that adds the confirmation — a done line and an open line about the same fact are not two different data points, they are one fact recorded twice and only updated once.

The backend is on Render’s free tier, and guests will hit a cold start.
